# Same-session review of executable normal generation and normalized output

This records the mathematical and implementation checks for this development round. Successful compilation and source identity are recorded separately in executable_verified_metadata.json. It is not an independent external review or a claim that the full bit-complexity theorem is complete.

## Finite normal generator

For an s-by-d integer matrix, normalSearchKeys explicitly enumerates r=0,...,d and all row and column maps. The row map need not initially be injective. tryNormalKey rejects noninjective column maps, rejects a zero pivot determinant, and checks the integer dot products of every original row against all returned Cramer normals. A nonzero minor and these annihilation tests certify the complete original row space by checked_candidate_describes. Conversely, normal_candidate_exists supplies a successful enumerated key. Existence is used only in the proof of isSome: computedMatrixNormals extracts the actual first successful Option result and does not select an existential witness.

The data path uses laplaceDet on the pivot and updated-column matrices. concreteColumnNormal_eq proves equality with the previously verified mathematical Cramer construction. For rank zero, the empty determinant is one and the resulting family is the identity. For full column rank, all normal equations vanish. For no original rows, the family characterizes the zero row space. These cases are included in the general proof and in separate runtime checks.

Count points are enumerated by the explicit relation countLexLE, which compares their finite coordinate lists lexicographically. This does not change the usual pointwise order on Counts. The initial local LinearOrder approach failed elaboration because the competing pointwise order was selected; the named relation fixes that ambiguity. The conversion between Fin(q+1) augmented integer rows and the existing rational pair space is a linear equivalence. computedCountForms has exactly q+1 entries; redundant zero forms are permitted.

## Quantities actually bounded

The finite generator is correct for arbitrary s and d. Its parameter-only enumeration bound additionally assumes s<=d and d>=1. SearchStates tracks B.card+fuel<=q+1, so every actual basis-search state satisfies s=B.card<=q+1=d. Hence there are at most (q+2)(q+1)^(2(q+1)) candidate checks per invocation and at most q+1 invocations per cell. This is a count in the explicit candidate-call accounting function, not a full machine runtime. computedCountForms binds the search result before mapping the normal entries. The candidate coefficient family is now materialized as nested finite lists with a proved lookup-equality theorem before annihilation checks. StoredExtrema materializes the searched lower/upper witness coordinates, derives low/high endpoints from these stored witnesses, and proves equality with the original extrema structure. The actual returned-family path uses it before mode enumeration. These explicit tables still require operational cost accounting before mathematical call budgets can be claimed as counts of compiled callback invocations. Semantic equality alone does not prove that a backend caches function evaluations.

Generated form coefficients obey the same 2(q+1)!N^(q+1) magnitude bound as the previous classical family. ComputedSearchPayload connects the new forms to the exact appended scalar query, parity substitution, row indexing, dense signed integer payload and every recursive search state. No arbitrary rational extra row is silently declared integer-bounded.

NormalCheckIntermediates bounds normal entries and annihilation products for every injective-column candidate, including rejected candidates. Every partial sum before cancellation has magnitude at most 2 d d! N^(d+1). The proved slightly looser bit bound is (clog_2(d+1)+clog_2 N)(d+1)+2. Together with the earlier determinant-intermediate bounds, this controls these arithmetic values. Enumeration, injectivity testing, index/storage costs, and multiplication bit costs still need explicit total accounting.

## Executable normalized output

computedParityFamily tests the row solver's actual Option result before forming a nonempty-parity witness. computedSelectionFamily and computedReturnedSets use computable finite unions/images. The edge witnesses are actual extracted solver answers. Equalities with the structural selection and returned family preserve all existing tightness and span results.

orderedBinarySets compares finite nested bit lists in class/item coordinate order. Its key is injective, giving a deterministic finite enumeration without a classical Finset.toList choice. computedReturnedBasis invokes the verified rank-guided basis search on that list. Correctness uses the existing returned affine span and independence proof, not a cardinality-only substitute for independence.

executableNormalizedPipeline computes invalid, empty and supported branches. In the supported branch it obtains an actual tight affine basis B, then returns dimension B.card-1 and facet flag B.card=n. This is valid because B.card equals the actual face dimension plus one, and the original well-formed knapsack polytope is full-dimensional. The same correctness contract includes tightness, affine independence, exact affine span, and basis cardinality. The normalized procedure and the original-coordinate relabeling have computable definitions; ILP and exact rank remain explicit supplied primitives. executableRecognitionBranch also replaces the old classical parityList with allFinFunctions q 2. Its support completeness and 2^q call bound are proved for this actual enumeration.

## Manuscript relation and remaining boundaries

The structural lemmas and geometric definitions are unchanged. The finite normal search replaces the manuscript's parameter-sized rational elimination; its candidate count has the intended parameter-only form. The normalized output obtains dimension from its extracted affine basis, which the manuscript already permits as output. These are algorithms with the same verified mathematical contract, not claims of line-for-line identical execution.

The implemented coordinate extrema still use finite scanning, not the manuscript's sharper binary-search query count. normalizeRawExecutable uses sorted integer coefficient values, sorted finite item fibers, and the computable Tuple.sort permutation for within-class weights. This replaces both Fintype.equivFin data choices. The old normalizeRaw remains as a historical interface, while executable_original_input_output_contract uses the computed normalization. The frozen model and targets are unchanged. Complete preprocessing runtime and operation/bit-cost composition, primitive exact-rank/ILP algorithms and the compression corollary remain open. No conclusion of complete paper or complete FPT formalization follows merely from the executable definitions or the declaration count.
